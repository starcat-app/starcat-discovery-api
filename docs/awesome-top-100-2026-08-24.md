# Awesome 来源 Top 100 候选清单（2026-08-24）

## 1. 目的与边界

本文档固定本轮准备导入 Discovery API 的 Awesome 来源候选集，供生产写入前人工复核。本文档不是应用内置数据，也不会被服务启动时自动导入。

- 排名查询：`topic:awesome-list awesome in:name archived:false fork:false`
- 排序方式：GitHub Search API 按 `stars` 降序
- 快照时间：2026-08-24（Asia/Shanghai）
- 查询结果总量：8,809 个，GitHub 返回 `incomplete_results = false`
- 候选约束：非 fork、未归档、名称包含 `awesome`、具有 `awesome-list` topic
- README 初筛：下列 100 个仓库均可通过 GitHub README API 读取
- 本轮范围：仅形成并提交可审阅清单，不部署服务，不写入生产数据库

Star 数是时间点快照，会随 GitHub 实时变化。本轮生产导入若获确认，以本文档固定的仓库顺序为准，不因短期 Star 波动重新排序。

## 2. 字段映射与生产门禁

导入时通过现有 Admin API 创建、同步和发布来源，不在应用或服务代码中写死清单：

- `id`：`owner/repo` 转为小写 kebab-case，例如 `sindresorhus/awesome` → `sindresorhus-awesome`
- `repo_full_name`：表格中的 GitHub 仓库全名
- `display_name`：仓库名
- `image_url`：GitHub 仓库所有者头像 URL
- `summary_en`：GitHub 仓库 description
- `summary_zh`：表格中的中文简介
- `featured`：全部为 `false`
- `sort_order`：表格排名，范围 1–100

README 可读取只代表初筛通过。生产导入时每个来源仍必须经过现有同步解析器；只有满足以下条件才能发布：

1. 仓库仍公开、未归档且默认分支可读取。
2. README 能被现有 AST 解析器解析。
3. 至少解析出 1 个有效的公开 GitHub 项目。
4. 同步状态为 `ready` 后才能执行发布。

如果某候选在生产导入时不满足门禁，则不发布该来源，并从同一查询的第 101 名开始依次补位，直至最终发布数达到 100；补位项需要再次提交人工确认。
